# TableLane
Navigate Your Data

Select a saved connection and click Edit connection… to change its settings or delete it. Deleting requires confirmation and only removes the saved connection; database data and open tabs stay available. Editing affects future connections; existing tabs keep their current session. Sessions retained after editing or deleting a saved connection appear as “Previous session” entries in the sidebar, with their own Disconnect and Refresh metadata controls. They cannot reconnect using removed settings. Test connection in the add/edit form checks connectivity and metadata access without saving. Changes to the form invalidate a completed test result. Only MariaDB can currently pass the connection test.

Double-click a saved MariaDB connection in the left sidebar, or select it and press Enter, to connect. A green dot marks a connected session whose latest connection or health check succeeded; expand its databases to see tables. Connections use SQLx, with only MariaDB enabled for now. Idle sessions are checked about every 30 seconds, with a five-second ping timeout; busy sessions are skipped so checks cannot cancel a query. Transport errors from database operations also mark the session offline. A lost connection removes the green dot and shows an error with Reconnect available. Reconnection is explicit and uses a new database session.

Select a connection or one of its children to use Connect, Disconnect…, Reconnect…, or Refresh metadata in the sidebar. Disconnect and reconnect check all affected tabs, including inactive tabs, and block on unsaved row edits or running reads, queries, saves, schema changes, and exports. The confirmation explains that closing a session rolls back uncommitted SQL transactions and removes temporary tables and session variables. Cancelling keeps the session available. SQL drafts, completed SQL results and their exports, and applied table filters, sorting, and page survive disconnect. Table previews reload and Structure tabs refresh when a matching session reconnects; SQL drafts are never executed automatically. After unexpected connection loss, dirty row drafts stay available to cancel before reconnecting.

Refresh metadata reloads the database/table tree and table-name completions in existing SQL editors on the same session. It preserves current previews, SQL results, and applied table queries; use the table or Structure tab’s Refresh to reload those views. Failed metadata refreshes preserve the last successful metadata snapshot and show an inline error.

Double-click a table, or select it and press Enter, to show its data in the content area. The preview uses virtual scrolling and 1,000-row pages, with resizable columns. Previous and Next browse the matching results; Next is disabled on the last page. Refresh reloads the current page. NULL values are marked explicitly; binary values appear as hexadecimal text. Each table opens in its own tab. Reopening a table activates its existing tab and preserves its filters, sorting, page, and row edits.

Click Export CSV… or Export JSON… below a table to export all rows matching the applied filters in the current sort order, across every page. Save or cancel row edits before exporting. SQL tabs offer the same commands for the last completed first result set, including rows beyond the 1,000-row preview. SQL export uses the captured result and never executes the statement again; editing the SQL text does not change that result. The status reports the full result count.

Exports contain full text and binary values as hexadecimal strings. CSV includes a header, quotes every non-NULL value (including empty strings), doubles embedded quotes, and writes SQL NULL as unquoted `\N`; literal text `\N` is quoted. JSON is an object with `columns` and `rows` arrays; cells are strings or JSON `null`, preserving precision and duplicate column names. Files replace their destination only after the full export succeeds. Cancelling the save picker leaves files untouched, and export errors leave results available for another attempt.

SQL execution streams full results to private, unencrypted temporary files instead of keeping them all in memory. They are deleted when results are replaced or their tab closes (after any active export finishes), and on normal app shutdown; a crash can leave temporary files behind. Large results require enough local disk space and hold the shared database session while being captured or fetched. Table export reads current database values, which may differ from an earlier preview after concurrent changes.

Click a column header to cycle through ascending, descending, and default ordering. Sorting runs in MariaDB on the original column values, with primary-key columns used to break ties. Tables without a primary key use all columns as the default ordering. Filtering or sorting returns to the first page.

Choose All columns or a specific column, then select a condition and enter a value. Results update 300 ms after typing stops; Enter or Apply searches immediately. Typing remains available during a query, and the latest search runs after it finishes. Conditions include contains, does not contain, equals, does not equal, starts with, ends with, greater than, greater than or equal, less than, and less than or equal. All columns matches any column; negative conditions require no column to match and ignore NULL columns. Numeric comparisons use the original column values. Filters match full values, including text beyond the truncated preview; binary columns match hexadecimal text. Apply filters to additional columns to combine them with AND. Selecting a column shows its current condition and value; applying an empty value removes that column's filter. Clear filters removes all filters. NULL values do not match text filters. Filter matching follows MariaDB's collation rules.

Save or cancel row edits before filtering, sorting, refreshing, or changing pages. Pages are live queries rather than a snapshot: concurrent inserts, deletes, or changes to sort values can shift rows between pages. Large offsets, substring filters, and sorting tables without a primary key can be slow on large tables.

Open a table and click Structure in the top toolbar to inspect its columns, indexes, foreign keys, and full CREATE statement. Each table has one Structure tab; reopening it activates the existing tab. Refresh reloads the metadata.

The Columns section offers Add column, Modify column (including renaming), and Drop column. Column forms edit the name, MariaDB type, nullable flag, default SQL expression, and comment; existing collation and extra attributes are preserved. Generated columns use Edit SQL to preserve their expressions. The Indexes section offers Add index and Drop index, including primary-key removal. Index columns accept SQL such as `` `name`(20), `id` ``; Unique index creates a unique index. Foreign-key changes and other advanced changes use Edit SQL, which opens a SQL draft for the selected table.

Every schema form previews the exact ALTER TABLE statement before applying it. MariaDB DDL commits immediately and cannot be rolled back; dropping a column deletes its data, and changing a type can convert existing data. Failed changes preserve the form for correction. Save or cancel row edits and wait for table operations before applying a schema change. While it runs, affected row editors are disabled. Successful form changes refresh the structure and reset the table preview's filters, sorting, and page. Changes run through Edit SQL require manually refreshing the Structure and data tabs.

Open a table and click the SQL editor icon in the top toolbar to run one SQL statement against that database. SQL keywords and table names from the selected database are suggested as you type; use the arrow keys and Enter to choose, or Escape to dismiss. Table suggestions use metadata loaded when connecting or refreshing metadata. Select SQL text to run just that selection, or leave the selection empty to run the whole editor. Click Run or press Cmd+Enter (Ctrl+Enter also works). The executed selection is what appears in SQL history. Press Cmd+/ to toggle SQL line comments on the current line or selected lines; Cmd+Z undoes the change. Results show the first 1,000 rows of the first result set, NULL values, binary values as hexadecimal, affected rows, elapsed time, and database errors. Statements execute directly, including writes and DDL; there is no automatic rollback or cancellation. Each click opens a separate SQL tab for the current connection and database. The editor header shows the selected database. SQL text and results stay available while switching between tabs.

Tab labels show the connection and database, with `Edited` for unsaved row changes, `Draft` for SQL text, and `Running` while a statement executes. Click a tab to switch, or use Ctrl+Tab and Ctrl+Shift+Tab. The tab bar scrolls and offers an overflow menu when needed. Click a tab’s close button or press Cmd+W (Ctrl+W also works) to close it. Closing a table with unsaved edits returns to its row editor; save or cancel before closing. Closing a SQL draft asks before discarding its text. Tabs with running queries, metadata reads, row saves, or exports cannot be closed. SQL and table tabs automatically save their drafts or applied filters, sorting, page, labels, order, and selected tab to `workspace.json` beside the settings file, 300 ms after editing, successful table query changes, or switching tabs. Closing or quitting flushes the current workspace immediately. Confirming discard removes the SQL tab from recovery as well.

On restart, SQL and table tabs reopen offline, even if their saved connection was deleted or is unavailable. SQL drafts remain editable. Double-click the matching saved connection in the sidebar to enable Run and reload available tables with their saved filters, sorting, and page. Table results are live queries, so restored pages can differ after database changes. Unavailable tables stay offline; a query using removed columns shows an error and offers Retry or Reset filters and sorting. Recovery matches the database kind, host, port, username, configured database, and file path; changing a connection name or password preserves that identity. Drafts for unavailable databases stay offline. Restoring tabs or connecting never executes SQL drafts. Results, unsaved row edits, undo history, and text selection are not restored. Structure tabs still live only for the current app session; when one was selected, restart selects the first recovered tab. Existing SQL-only workspace files remain readable.

Draft text, table filters, and connection identity are stored locally as plain JSON with private file permissions; connection passwords are excluded. The recovery file uses the existing 1 MiB JSON limit. Invalid files are preserved and autosave is disabled until the file is fixed and the app restarts. Failed writes preserve the previous recovery file and show an inline error with Retry autosave. App Quit commands and the window close button wait for running connections, queries, row saves, schema changes, and exports. They ask before discarding unsaved row edits, including edits in inactive tabs, or closing when workspace recovery cannot be saved. Cancel keeps all edits available; confirming discard closes without writing those row edits to the database. OS termination cannot be cancelled at the app's final shutdown hook; a crash or forced termination can lose text typed since the last autosave. Forced termination can also lose row edits or interrupt running operations; the normal Quit and window-close guards cannot prevent it.

Cell previews fetch at most 200 text characters or 100 binary bytes, plus a small lookahead to detect truncation. Longer values end with `…`. Selecting a row opens the right sidebar and loads its full values for editing. A single `Edited` status appears at the top when values change; press Cmd+S to save to MariaDB or Escape to discard the draft. Save and Cancel buttons provide the same actions. Unsaved edits must be saved or cancelled before switching rows within a table or closing its tab.

Saving requires an InnoDB table with a primary key. Saves check the original row for concurrent changes and roll back failed or lossy conversions. Generated, spatial, and bit columns cannot be edited; binary fields use hexadecimal text. Use the Use NULL checkbox to explicitly save SQL NULL. Uncheck it to enter text, including an empty string. NULL fields disable text editing; toggling the checkbox preserves the text draft so the choice can be reversed before saving. Database constraints still validate whether a column accepts NULL.

Click History… beside Run to see completed SQL commands for the current connection name and database, newest first, including failures and execution status. Click a history row to load its SQL, or use the arrow keys and Enter. Loading replaces the editor text without executing it; Cmd+Z restores the previous draft. History keeps the latest 100 commands across all connections and survives app restarts in `sql-history.json` beside the settings file. SQL text and database errors are stored locally as plain text; history is separate from settings exports. History load or save errors appear in the history dialog.

Run the application test suite with `cargo test --locked -- --test-threads=1`. Parallel runs can intermittently fail UI state assertions; serial execution passed the current suite.

Live MariaDB tests require an isolated server containing `tablelane_test.widgets` and an empty `empty_db` database, with a passwordless `root` account. Run them with `TABLELANE_TEST_MARIADB_PORT=<port> cargo test --locked mariadb_ -- --ignored --test-threads=1` (serial execution avoids shared fixture interference).

Connection passwords are encrypted with AES-256-GCM in settings JSON and settings exports, using a fresh random nonce for each save. Older plaintext passwords still load and are encrypted on the next save.

The encryption key is embedded in `src/settings/password.rs` and can be recovered from the app. Keep it stable: changing it makes existing encrypted passwords unreadable. Use an OS keychain if stronger credential protection is needed.
